# L05 — per-connection admission and queue pressure

Revision 156, 2026-11-02. Internal unit implemented and tested. It does not
configure the broker or OS or install or activate a helper. L05 remains E;
execution is OFF by default.

## Scope and order

PrivilegedAdmission is a token bucket shared by the two endpoints of one
RECEIVER CONNECTION, with another bucket per unique sender assigned by
D-Bus. It is not per UID, person, process, or system. Opening another client
connection changes its key but does NOT reset the receiver's shared bucket.
Opening a new receiver creates a separate limit; future helper configuration
must control how many receivers exist. Payload claims are not treated as
identity.

admit_request checks the owned connection, current message, and message
type 1. It takes the sender from the broker header and reads local queue
counters, without identity or polkit RPCs. Rejection creates no
[revision 155 budget](LINUX_PRIVILEGED_BUDGET.en.md) and performs no preflight,
identity, Authority, or Manager work for the requested flow. Local connection
and metadata validation and reply generation still have a cost. The control
OFF/busy gates return even earlier through their low-cost path. They are not
counted as admitted and consume no quota.

## Protected configuration fixed per receiver

PrivilegedBusEndpoint is configured only by the C++ mechanism, never by a
message:

| Parameter | Default | Range |
| --- | ---: | ---: |
| Shared burst / refill per second | 64 / 16 | 1–512 / 1–1,024 |
| Per-sender burst / refill per second | 16 / 4 | 1–512 / 1–1,024 |
| Stored senders | 64 | 1–256 |
| Idle expiration | 300 s | 1–300 s |
| Read / write queue threshold | 64 / 64 messages | 1–1,024 |

The idle interval must be at least the time it takes to refill a sender
bucket completely, so expiration and recreation cannot grant credits early.
Zero does not disable the guard; invalid configuration rejects the connection.
Regression profiles explicitly use burst 256 and rate 512; they do NOT
change the production defaults.

Credits are integer microtokens, with no floating point. The implementation
uses a monotonic clock and mutex and retains fractional credit. The shared
bucket is charged first: per-sender or full-table rejections also consume
shared quota. A full table rejects new keys without evicting active ones.
Only idle entries expire. Rejections when the shared quota is exhausted do
not add keys. An invalid or backwards clock or allocation failure disables
the instance; a client request cannot reset it. There is no deferred request
queue, retry, wait for refill, or fallback.

The guard does not guarantee fairness. Clients with multiple connections
can bypass the per-sender limit or fill the table until entries expire. The
shared quota and bounded memory still protect that receiver. There is no
guarantee against system-wide denial of service.

## What queue pressure means

sd_bus_get_n_queued_read/write observe messages already queued in the bus
object. If either count exceeds its threshold, work is rejected before
expensive RPCs. An error or missing symbols causes rejection, not an assumed
zero. There is no implicit flush, drain, close, or cancellation of earlier
operations.

This is NOT a hard limit on queues, bytes, messages, sockets, the broker,
or memory before sd-bus decoding. The counters are read AFTER receipt.
Transport resources can already be consumed before the handler. The host
must define backpressure, connection closure, and bounded replies under
write pressure. This guard does not limit replies generated by other code
or signal traffic. Transport and broker configuration and pre-receive limits
remain pending. Host configuration is not changed to simulate those guarantees.

## Revision 156 evidence

charging rejections, partial and exact refill and idle expiry, a full table
without active eviction, safe TTL, injected read/write pressure and boundaries,
invalid sender and configuration, sub-microsecond clock reversal and clock
failure, and 32 threads with exactly one admission.

broker and REAL libsystemd and SIMULATED Authority and Manager. Shared burst
3, sender burst 2, and refill rate 1 authorize one request, execute one
MODELED operation, and reject three more. Control and authorization-only
share credits. A new sender on the second client does not bypass the shared
quota. Rejected control has no budget or dispatch; rejected authorization
has no check. Counts stop at five requests, two checks, one Manager call,
and one Subscribe. No real service is affected. Normal native queue counter
reads were verified; real queues were not flooded in this unit.
