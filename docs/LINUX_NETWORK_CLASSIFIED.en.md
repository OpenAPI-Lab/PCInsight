# Four TCP/UDP and IPv4/IPv6 counters (F03 in progress)

This page describes revision 29. Revision 30 adds identity checks and guards
in the private --authorized-quality mode; see [counter quality](LINUX_NETWORK_QUALITY.en.md).
Earlier modes retain their historical limitations.

Revision 29 extends the private capability test, not a production collector.
`make_private_classified_network_probe` in linux_network_probe generates
bytecode directly without external tools. It still filters exactly one kernel
TGID before reading context, socket data, or maps. Identity comes from local,
unattached TEST_RUN; it is never assumed to match getpid.

## What changed

Send uses inet_sendmsg and inet6_sendmsg, not the sendto syscall or
sock_sendmsg. BTF validation checks their int32 return type and the
socket*, msghdr*, and 64-bit size_t arguments. Receive still uses
sock_recvmsg, whose signature was already validated. All these hooks have
three arguments and the fexit return at offset 24. Missing inet hooks have
ID 0: this is not a valid hook, and it does not invalidate the rest of the
layout. A present hook with an ambiguous or incompatible signature causes
layout rejection. The native classified test needs both inet hooks to
demonstrate positive IPv4 and IPv6 coverage.

After filtering TGID and dropping nonpositive int32 returns, the probe gets
socket* from the selected context and reads socket.sk, skc_family, and
sk_protocol through probe_read_kernel. Offsets and the one- or two-byte
protocol width come from validated BTF, not constants from another version.
Scratch stack space is fully initialized before each read. Null pointers
and errors are counted; a failed read is not treated as a known zero family
or protocol.

Only AF_INET/AF_INET6 and IPPROTO_TCP/IPPROTO_UDP feed the four lanes.
Other protocols and families are out of scope, not reclassified by port
or process name. The owned u32-to-u64 ARRAY map has six entries:

| Index | Meaning |
| --- | --- |
| 0 | TCP send, bytes from positive returns |
| 1 | TCP receive, bytes from positive returns not excluded |
| 2 | UDP send, bytes from positive returns |
| 3 | UDP receive, bytes from positive returns not excluded |
| 4 | Positive operations with a failed read or socket lookup |
| 5 | Positive receives excluded by flags |

MSG_PEEK, MSG_TRUNC, and MSG_ERRQUEUE are excluded from received bytes and
increment entry 5. This is the test's conservative policy: a peek does
not consume data, a TRUNC return may not describe copied bytes, and
ERRQUEUE is not ordinary payload reception. That exclusion is not hidden
behind a claim of complete accounting. Flags are checked before reading
the operation's socket. Other flags such as DONTWAIT are not excluded
on their own. Errors and zero returns contribute no bytes and are not
counted as excluded positive receives.

## Tests and authorization

The manual linux-network-probe-native executable adds --authorized-classified.
It uses the explicit human authorization from 2026-10-18 for private WSL
processes only, with temporary root and final cleanup. No pinning, permanent
configuration, or tool installation. The privileged test is not registered
in CTest. Neither the earlier mode nor this one loads probes without an
explicit argument.

Portable fixtures in tests/linux_network_classified.cpp cover TCP/UDP,
IPv4/IPv6 families, one- and two-byte widths, early filtering without reads
of unrelated processes, each helper failure and null pointer, out-of-scope
families and protocols, flags, returns/errors/signedness, null lookups, and
invalid layouts. The interpreter handles only the generated bytecode; it
does not replace the kernel verifier. BTF tests cover missing optional inet
signatures, wrong size_t, ambiguity, and an extern function that cannot be
attached.

Positive native WSL 6.6.114.1 result: TCP/UDP over IPv4/IPv6 using both
send/sendto and sendmsg, with 1,024 B TCP and 64 B UDP per case. Contents,
returns, and counters were checked per phase. TCP totals were 4,096/4,096,
UDP 256/256, with zero read failures and eight excluded peeks without double
counting. A private child repeats both APIs and families without incrementing
the allowed TGID's map. Repeating everything after all three links close
also leaves counters unchanged, verifying teardown. The earlier unclassified
test still passes. Logs: work/network-classified-sendmsg-native-linux.log and
work/network-classified-legacy-native-linux.log. The first positive run, before
sendmsg was added, is retained in network-classified-native-linux.log.

Final Release regression: Linux 101/101 (native BTF passed, not skipped)
and Windows 115/115. Final builds had no warnings. Installed consumers on
both systems were relinked and exited 0. Logs under work/:
network-classified-suite-{linux,windows}.log, network-classified-final-build-linux.log,
and network-classified-build-windows.log, plus install/consumer logs with
the same prefix. The final live classified test exited 0, with visible PID
1281 and kernel TGID 3721. Historical N03 risks remain open; these suites
do not establish that they were fixed.

## Limits: this is not a finished provider

The four counters belong only to this private test. There is no map keyed
by actor/UID/start_boottime/network namespace cookie, reusable process token,
production snapshot consistency, uint64 saturation detection, or complete
global loss accounting. Entry 4 counts only failures of instrumented reads.
It does not establish complete coverage or absence of other losses. Test
counters can overflow and must not be published without the future saturation
guard. The allowed process stays alive throughout the test.

This does not test sendmmsg/write/splice/io_uring/asynchronous operations,
other protocols, physical interfaces, wire bytes, ACKs, or retransmissions.
Socket fields read on return are not an immutable token for socket state at
operation entry. There is no deduplication by socket or cookie: these are
operation returns for the observed actor, not exclusive ownership of a
shared socket.

The map does NOT yet satisfy the [revision 27 reducer contract](LINUX_NETWORK_ACCOUNTING.en.md).
It is not connected to LinuxNetworkAccounting, Monitor, ProcessInfo/UserSession,
or history. No new public API, existing layout changes, virtual ABI changes,
or history formats. At this checkpoint, F03 remains E, and J04/H04 stay open.
The producer still needs identity, quality and consistency checks, saturation
handling, declared coverage, and public integration. This test does not add
a closed ID to raise the completion percentage.
